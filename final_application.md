### **[НАЗВАНИЕ ПРОЕКТА]**

"Place Pace – платформа умных туристических маршрутов по Москве"

---

### **[ПРОБЛЕМНОЕ ПОЛЕ]**

Современные туристы в Москве сталкиваются с **отсутствием** интеллектуальных инструментов для планирования маршрутов, которые учитывали бы все ключевые параметры посещения достопримечательностей. **Невозможность** эффективно объединить в одном решении расписания работы мест, транспортную логистику и бюджетные ограничения приводит к **потере** 30-40% времени на логистику и **снижению** количества посещаемых мест. Дополнительная сложность — **незнание** местных особенностей (часы работы, лучшие периоды для посещения). Существующие аналоги **не предоставляют** комплексного подхода к оптимизации временных затрат и **не учитывают** динамические факторы городской среды.

### **[ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ]**

**Основные группы пользователей:**

*   **Иностранные туристы в Москве**, не владеющие русским языком, нуждающиеся в преодолении языкового и культурного барьера, а также в помощи с навигацией в незнакомом городе.
*   **Иногородние туристы из России**, приезжающие в столицу на короткий срок и желающие максимально эффективно осмотреть главные достопримечательности.
*   **Семьи с детьми**, путешествующие самостоятельно, для которых критически важны логистика, учет времени на перемещение и подбор подходящих детских активностей и мест питания.
*   **Деловые туристы (бизнес-путешественники)** с крайне ограниченным свободным временем, которым необходим инструмент для быстрого планирования кратких и насыщенных культурных программ между встречами.

**Косвенная аудитория / Потенциальные партнеры:**

*   **Владельцы и управляющие POI (Points of Interest)**: музеи, рестораны, развлекательные центры, заинтересованные в привлечении целевого потока туристов.

### **[ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ]**

1. Конструктор персонализированных маршрутов
2. Учет расписаний работы мест посещения
3. Интерактивная настройка времени осмотра и приоритета каждой точки в маршруте
4. Оптимизация маршрута с учётом нескольких видов транспорта (пешком, метро, МЦК/МЦД, автобус, трамвай, такси, речной транспорт) и начальной/конечной точки (дом/отель)

6. Калькулятор стоимости маршрута
7. Выбор режимов передвижения
8. Публикация маршрутов в открытый доступ, поиск и адаптация чужих маршрутов, редактирование собственных
9. Экспорт маршрута в PDF, по ссылке или в JSON
10. Аккаунты пользователей с подтверждением e-mail
11. Отдельный мобильный режим пошагового прохождения маршрута «On It» с живым сдвигом расписания по факту
12. Мультиязычная поддержка интерфейса (русский, английский)

### **[ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ]**

* **Яндекс.Карты** - предоставляют routing, но **не учитывают** расписание работы достопримечательностей и **не оптимизируют** порядок посещения точек
* **Tripadvisor** - имеет базу отзывов, но **отсутствует** функция интеллектуального планирования маршрутов
* **Гугл "Мой план"** - позволяет создавать маршруты вручную, но **не предоставляет** автоматической оптимизации по времени и логистике

В отличие от перечисленных аналогов, Place Pace дополнительно позволяет:
* **Сохранять** построенные маршруты в личном профиле, а не только использовать их разово
* **Проходить маршрут в реальном времени** (режим «On It») с живым сдвигом расписания по факту, если что-то пошло не по плану
* **Публиковать маршруты в открытый доступ и адаптировать** чужие опубликованные маршруты под себя
* **Добавлять маршруты в избранное**
* **Искать маршруты** по создателю, содержанию (входящим в него достопримечательностям) и названию, а также просматривать подборки по рейтингу

### **[ИНСТРУМЕНТЫ РАЗРАБОТКИ]**

**Инструменты разработки:**
* **Фронтенд:** React + TypeScript + Vite + Tailwind CSS
* **Бэкенд:** Python + Flask + SQLAlchemy + PostgreSQL + Google OR-Tools
* **Карты и транспорт:** OSRM (собственный сервер маршрутизации), OpenTripPlanner с построенным GTFS-графом транспорта Москвы, Яндекс.Геосаджест/Геокодер (адреса), Яндекс.Go API (такси), 2GIS Catalog API (места и рестораны)
* **DevOps и инфраструктура:**
* - Docker + Docker Compose (контейнеризация, разработка и продакшен)
* - nginx + certbot (reverse proxy и TLS-сертификаты на VPS)
* - GitHub Actions (CI/CD для автотестов и линтинга)
* **WSGI сервер:** Gunicorn (продакшен-запуск Flask)
* **Мониторинг и аналитика:**
* - Базовый мониторинг ресурсов сервера (CPU/RAM/диск/сеть) в панели управления Timeweb Cloud
* - Базовое логирование через Python logging

### **[ВОЗМОЖНЫЕ РИСКИ]**

* **Неактуальность данных** о достопримечательностях - решение: синхронизация базы мест с внешним каталогом (2GIS Catalog API)
* **Низкая производительность** при сложных расчетах - решение: кеширование результатов и оптимизация запросов
* **Сложность интеграции** с API транспортных служб - решение: поэтапное подключение видов транспорта - сначала пешие маршруты через OSRM, затем общественный транспорт через OpenTripPlanner с построением GTFS-графа
* **Недостаточное участие** бета-тестеров - решение: привлечение заинтересованных друзей и знакомых, упрощение процесса тестирования
* **Сложности с настройкой продакшен-инфраструктуры** - решение: разделение подготовки конфигурации (Docker, docker-compose) и самого развёртывания по пошаговому runbook, чтобы снизить риск ошибок при ручной настройке VPS.
